# Caravan Lean — новий сайт: правила для агента

Покласти в корінь репо `caravan-lean-site` як `CLAUDE.md`. Агент читає цей файл на старті кожної сесії.
Повний план і аналіз — `docs/NEW_SITE_GUIDE.md`. Стан — `STATUS.md`. Задачі — `TODO.md`.

## Що робимо

Новий інтернет-магазин замість старого **shop.caravan-lean.com.ua** (Joomla 2.5 + VirtueMart, 2012–2014 рр.)
на тому ж хостингу («Хостинг Україна», ukraine.com.ua). Плюс дані для мобільного застосунку Caravan Lean
(репо `faric-ua/caravan-lean-shop`, формат `catalog.json`).

## Люди

- **Виконавець** — працює на ноутбуці з Windows через меню `САЙТ` (`menu.cmd` / `menu.ps1`). Пиши українською, коротко, простими словами.
- **Власник магазину** — приймає рішення й робить остаточну перевірку. Без його «так» на робочий сайт нічого не йде.
- Дії людини — **пунктами меню**: `САЙТ → 10 → 11`. Команди руками — лише якщо пункту ще нема (і тоді додай пункт).

## Старт сесії

1. Прочитати `CLAUDE.md` → `STATUS.md` → `TODO.md`.
2. Статус — що на GitHub, чи живі сайти: `pwsh -NoProfile -ExecutionPolicy Bypass -File menu.ps1 -Run 2`
   (так само будь-який пункт, крім 3, 4, 12, 15, 17 — вони питають людину й запускаються лише з меню).
3. Неясно, що робити, — одне питання.

## Цикл роботи

1. Гілка `feat/…` / `fix/…` → PR у `main` → зелені перевірки → squash-мерж.
2. Спершу **локально** (пункт 7) → потім **тестовий сайт** (пункт 11) → власник дивиться → **робочий** (пункт 12).
3. **Резервна копія (пункт 10)** — перед викладанням на робочий сайт (пункт 12 без повної копії за сьогодні не пустить)
   і перед будь-якою ручною зміною в панелі хостингу (база, папки, PHP, DNS). Тестовий сайт (11) — без копії.
4. Пункт 12 викладає лише код (тема/плагін). Запуск нового сайту (етап 7) — окремий чек-лист з інструкції, по кроках з людиною.
5. Результат — у `STATUS.md` (дата, що зроблено, хто перевірив).

## Докази (не плутати)

Код ≠ тест ≠ зелений CI ≠ працює на тестовому сайті ≠ **власник сказав «так»**. Пас ставить лише людина.

## Заборонено

- Класти в репо паролі, ключі, `wp-config.php`, `.env`, дампи бази, архіви сайту, дані клієнтів (імена, телефони, адреси, замовлення).
  Дампи й архіви — лише на Google Диску в папці **власника** (`DrivePath\backups`), доступ — лише виконавцю й власнику.
- Міняти робочий сайт напряму (FTP/панель) в обхід пунктів 10–12.
- Видаляти старий сайт, базу чи пошту до окремого письмового «так» власника. Старий сайт лишається архівом щонайменше 3 місяці після запуску.
- Чіпати DNS і пошту домену (MX-записи) без плану з етапу 7 — пошта @caravan-lean.com.ua має працювати весь час.
- Сканери вразливостей, підбір паролів, будь-які «атаки» на сайт — навіть «для перевірки». Доступ — лише через дані, які дав власник.
- Зсувати номери пунктів меню (нове — наступним вільним номером).
- `git reset --hard`, `git clean`, force-push у `main`.

## Карта

| Що | Де |
|---|---|
| Меню Windows | `menu.cmd`, `menu.ps1`, `tools\*.ps1` |
| Налаштування ноутбука (не в репо) | `%USERPROFILE%\.caravan-lean\config.psd1` (шаблон `config.example.psd1`) |
| Локальна копія сайту | `docker-compose.yml` (пункти 7/8) |
| Тема і свій плагін (варіант A) | `wp-content/themes/caravan-lean`, `wp-content/plugins/caravan-lean-core` |
| Міграція зі старого сайту | `migration/` (скрипти; вхідні дампи — `migration/input/`, у .gitignore) |
| Викладання на хостинг | `.github/workflows/deploy.yml` (input `target`: staging / production) |
| Перевірки | `scripts/check.ps1`, `.github/workflows/checks.yml` |
